## Content rules

- The candidate brief must be self-contained and must not reveal follow-ups, hidden edge cases, solution structure, code, pseudocode, or hints.
- The interviewer plan may describe expected evidence and concepts, but must not contain a complete solution.
- Use zero to three follow-ups. Each follow-up must add meaningful learning value.
- Score and record difficulty using the six repository dimensions; the recorded rating must match task.md.
- Every stage has Start questions and Checkpoint questions sections with zero to two questions each; two is a target, not a quota.
- Question kinds are diagnostic, prediction, counterexample, tradeoff, transfer, or teaching. Every question needs a declared topic, prompt, purpose, and expected evidence.
- Start questions must diagnose reasoning without naming the intended technique, root cause, or hidden follow-up.
- Use only canonical topic IDs listed above.
- Include hasPreview and previewEntry in task.md only for a visible UI task.
- Do not output scaffold code; Codex creates it after import.
